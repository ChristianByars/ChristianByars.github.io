### Question 1
GitHub is a website that allows people to share files with others remotely and seamlessly. Doing this not only allows other people to access your code, but it also allows users to store copies of the repositories for multiple reasons. Developers have the ability to post changes they make in their repo incrementally, also known as version control. In a typical team work environment, members of the team would create different branches in order to make modifications to the project. Why do they branch? Branching allows developers to work in isolated environments without interfering with the “main branch” and other people's work. Once an individual in a shared code base has committed their changes, he/she would make what is called a pull request. Once a pull request is made, members of the team would have the ability to review the changes before making the changes final for the whole project. When it comes to non developers, github is also a resource for people (especially students!) to have access to frontier AI models. If you apply for it with your student email, you can get access to “premium” LLM usage. I put premium in quotes since they changed their policy from allowing people to pick a pool of different premium models, to an “auto” mode that picks the best model based on the request. Github is a platform that is primarily leveraged by people working in tech and software spaces, but is used by anyone that needs to share files seamlessly or wants AI tools.

A pull request is the action a developer takes when he or she has finished the changes they have made in order for someone else to review. If I make a PR in a shared repo, I would be requesting one of my teammates to pull my changes onto the main branch. Once a teammate of mine has reviewed the changes, my teammates or I can put the changes I made onto the main branch, also known as a merge.
